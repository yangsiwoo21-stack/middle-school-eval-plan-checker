# 작업 인수인계

학교 PC와 집 PC에서 번갈아 작업할 때, 작업 종료 전에 이 파일을 최신 상태로 갱신한 뒤 `upload_to_github.bat`으로 GitHub에 업로드합니다.

## 현재 작업 기준

- 기준 저장소: GitHub `yangsiwoo21-stack/middle-school-eval-plan-checker`
- 기본 작업 브랜치: `feature/desktop-eval-checker`
- 앱 위치: `평가계획 점검기/assessment_checker_app/`

## 작업 시작 전

1. `깃허브 업데이트.bat` 실행
2. `git status`로 변경 사항 확인
3. 프로그램 실행 후 필요한 작업 진행

## 작업 종료 전

1. 오늘 수정한 내용 요약을 아래에 작성
2. 남은 문제 또는 다음 할 일을 아래에 작성
3. `깃허브 업로드.bat` 실행

## GitHub 배치파일 사용법

### 깃허브 업데이트.bat

- 작업 시작 전에 실행합니다.
- 현재 로컬 폴더를 `_github_update_backups/` 아래에 먼저 백업합니다.
- `git fetch`, `git pull`을 실행해서 GitHub 최신 버전을 내려받습니다.
- 이 파일은 내려받기 전용입니다. `WORK_HANDOFF.md`를 GitHub에 올리지는 않습니다.

### 깃허브 업로드.bat

- 작업 종료 전에 실행합니다.
- 먼저 `WORK_HANDOFF.md`에 오늘 작업 내용과 다음 할 일을 적습니다.
- 민감 파일 경고를 확인하고 `YES`를 입력하면 진행합니다.
- 커밋 메시지를 직접 입력합니다.
- `git add .`, `git commit`, `git push`를 실행합니다.
- `WORK_HANDOFF.md`가 수정되어 있으면 다른 변경 파일과 함께 GitHub에 업로드됩니다.

### 다른 PC로 옮길 때

- 두 배치파일만 따로 실행하면 안 되고, Git 저장소 루트 폴더에 두어야 합니다.
- 저장소 루트에는 `.git`, `.gitignore`, `WORK_HANDOFF.md`, `깃허브 업데이트.bat`, `깃허브 업로드.bat`, `평가계획 점검기/`가 함께 있어야 합니다.

## 최근 작업 요약

- 민감 파일이 GitHub에 올라가지 않도록 `.gitignore` 정리.

## 2026-07-02 내촌중 3학년 교육청 컨설팅 기준 추가 학습

- 국어: `서평쓰기`에서 `독서일지 작성하기`, `서평 쓰기` 평가요소 만점과 채점표 최고 배점이 서로 뒤바뀐 유형 확인. 이미 `평가요소 만점-채점표 배점 불일치` 규칙으로 반영.
- 국어/수학: 정기시험 논술형 평가 비율이 `4%`인 경우 학업성적관리규정의 정기시험 논술형 평가 비율 기준과 대조 필요.
- 역사/도덕/수학/과학/기술가정/체육/영어/정보 등: 월별 교수학습 운영계획의 `수업·평가 연계` 내용 누락을 주요 오류로 봐야 함. 수행평가가 4번/6번에 있으면 월별 운영계획에도 해당 수행평가명 또는 평가 활동이 연결되어야 함.
- 역사: 4번 `평가의 종류와 반영비율`의 평가 영역명과 6번 수행평가 세부기준의 평가영역명이 서로 맞는지 대조 필요.
- 역사: 채점기준이 `5~3점`, `7~3점`처럼 범위로만 되어 있으면 구체적 기준이 부족한 것으로 보고 보완 권고. 평가요소 아래에 배점 기록 권장.
- 과학: 수행평가 기간이 서로 겹치는 경우 확인 필요. 예: `화학읽기`와 `화학 반응 문제 해결하기`가 모두 4월 3주로 겹침.
- 과학: 수행평가 영역명이 다른 활동명으로 오기된 경우 확인 필요. 예: `운동과 에너지 논술하기`의 평가 영역명이 `한글 홍보 자료 만들기`로 기재됨.
- 기술가정: `평가의 목적`에 2015 기술가정 교육과정을 반영하여 교과 특성이 드러나는지 확인 필요.
- 기술가정: 수행평가 세부기준에서 평가요소 배점 위치가 잘못된 경우 확인. 예: `신재생 에너지 활용방안 제안하기`의 15점 평가요소를 오른쪽 표의 5점, 10점 평가요소로 나누어 대체 가능.
- 체육: 수행평가 영역명이 같은 영역으로 2개 존재하면 오류. 평가요소에 맞춰 수행평가 영역명을 각각 수정 필요.
- 음악: 수행평가 세부기준에서 평가요소 및 채점기준이 3개 등급으로만 제시된 경우 최소 5개 등급 이상 필요.
- 영어: 수행평가 세부기준에서 평가요소 및 채점기준의 권장 표현 확인. 예: `학교 체험학습 제안서`, `장단점 정리`, `자신 체험학습의 개선방안 쓰기` 등으로 정선된 표현 사용 권장.
- 정보: 4번 반영비율의 성취기준과 6번 세부기준의 성취기준이 다른 경우 오류.
- 정보: 수행평가 세부기준에서 평가요소와 세부 배점의 대응이 드러나지 않으면 오류. 특정 논술형 배점이 수행평가 1개 영역의 30% 초과인지 판단 가능해야 함.

## 2026-07-02 자가진단기 규칙 추가

- 자가진단기 용도는 선생님들이 제출 전 자기 과목 평가계획을 점검하는 것. 사람의 문맥 권고보다는 명확한 규칙형 오류 위주로 유지.
- 추가 규칙 1: `교수학습 운영계획 수업·평가 연계 누락`.
  - 4번 평가의 종류와 반영비율에 있는 수행평가 영역명이 월별 교수학습 운영계획 앞부분에서 확인되지 않으면 표시.
- 추가 규칙 2: `4번-6번 수행평가 영역명 불일치`.
  - 4번 반영비율 표의 수행평가 영역명과 6번 수행평가 세부기준의 평가영역명이 다르면 표시.
- 추가 규칙 3: `채점기준 범위형 배점`.
  - `5~3점`, `7~3점`처럼 점수 범위만 제시된 경우 각 배점별 기준이 불명확하므로 표시.
- 보완 규칙: 수행평가 영역 반영비율이 `50% (논술형)`처럼 점수 없이 비율만 적힌 경우도 30% 초과 여부를 검출.
- 확인 사례: 내촌중 1학년 국어 `정보전달 글쓰기(논술형)` 50% 항목이 `수행평가 한 영역 30% 초과`로 검출됨.
- HWPX 폰트/글씨색은 XML에 정보가 있어 기술적으로 추출 가능하지만, 현재 진단기는 텍스트·표 구조·점수·성취기준 중심으로 판단함. 색/폰트 기반 규칙은 필요 시 별도 파서로 추가.
